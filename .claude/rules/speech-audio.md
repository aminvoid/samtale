# Speech and audio

## Text-to-speech generation (Azure AI Speech)
- **Audio is pre-generated by a script, never on request.** The script outputs:
  - compressed mono audio files (format chosen in an ADR)
  - a **manifest** mapping each item ID to its URL, duration, voice, content hash and **word boundaries**: text, character offset, audio offset in ms, duration in ms
- **File names are content-addressed:** a hash of the text, voice, SSML settings and script version. Only changed items are regenerated, and files can be cached forever.
- **Voices:** fetch the current `da-DK` voice list from the Azure API rather than hard-coding names from memory. The final choice is recorded in an ADR after a listening test with the user. The examiner voice and the model-answer voice are different.
- **SSML:**
  - use `xml:lang="da-DK"` and escape XML characters
  - handle abbreviations and numbers (fx, f.eks., bl.a., ca., osv., mv., pga., years, ordinals) with `<sub alias>` or a lexicon when the voice gets them wrong
  - the text shown on screen never changes
- **Robustness:**
  - limit concurrency and retry with exponential backoff
  - make generation resumable
  - provide `--dry-run`, which prints the character count and a cost estimate
- **Before any large or paid run,** ask the user and show the dry-run numbers.
- **Check pricing and free-tier limits** in current Azure docs. Don't assume them.

## Secrets
- **Environment variables:** `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION` (or Entra ID credentials) come from the environment and are validated with Zod.
- **Never** log them, commit them or expose them through `NEXT_PUBLIC_*`.
- **Browser speech features (future speech-to-text)** use short-lived tokens issued by a server route.

## Playback (client)
- **One shared player:** only one clip plays at a time, through a single player context.
- **Loading:** `preload="none"` (or `metadata` when duration is needed). Show loading and error states with retry.
- **iOS Safari:** start playback only from a user gesture. No autoplay.
- **Speed:** 0.75× / 1× / 1.25× with `preservesPitch`.
- **Word highlighting** comes from the manifest timings. Respect `prefers-reduced-motion`.
- **Controls** have translated accessible names. The play icon is not mirrored in RTL.

## Recording (client)
- **Permission:** ask for the microphone only after a user action, and explain why in Persian first. Handle denial with clear guidance.
- **Format:** pick it by feature detection (`MediaRecorder.isTypeSupported`). Safari usually needs `audio/mp4`, while Chromium and Firefox use `audio/webm`.
- **Cleanup:** stop all tracks on stop or unmount, revoke object URLs, and enforce a maximum duration.
- **Storage:** recordings stay on the device (in memory, or IndexedDB if kept). Users can delete them. They are never uploaded in v1.
